# nas-app 打包为 .fpk 说明

本文档说明如何把 `nas-app/` 打包成飞牛 fnOS 可安装的 `.fpk` 应用包。

> 参考官方 fnpack 文档：<https://developer.fnnas.com/docs/cli/fnpack/>

## 1. 前置：安装 fnpack

fnpack 是飞牛官方打包工具（单文件可执行程序）。

1. 下载（任选其一架构）：
   - Windows x86：`https://static2.fnnas.com/fnpack/fnpack-1.2.3-windows-amd64`
   - Linux x86：`https://static2.fnnas.com/fnpack/fnpack-1.2.3-linux-amd64`
   - Linux ARM：`https://static2.fnnas.com/fnpack/fnpack-1.2.3-linux-arm64`
   - macOS：`fnpack-1.2.3-darwin-amd64` / `fnpack-1.2.3-darwin-arm64`
2. 下载后**改名去掉版本号后缀**为 `fnpack`（Windows 为 `fnpack.exe`）。
3. 放入 `PATH`，或记下绝对路径用环境变量 `FNPACK` 指定。

```bash
# Linux/macOS 示例
chmod +x fnpack
sudo mv fnpack /usr/local/bin/fnpack
fnpack --help    # 验证：应输出版本与命令
```

## 2. 项目结构（已是合法 fnpack 项目）

`nas-app/` 已按 fnpack 官方 Docker 模板组织，可直接 `fnpack build`，无需先 `fnpack create` 再覆盖：

```
nas-app/
├── manifest                 INI 格式元信息（appname/version/source/platform/desktop_*）
├── ICON.PNG / ICON_256.PNG  应用图标（占位，可替换）
├── config/
│   ├── privilege            JSON：运行身份（run-as=package，用户/组 bgi-trigger）
│   └── resource             JSON：docker-project 声明 + data-share 数据卷声明
├── cmd/                     生命周期脚本
│   ├── main                 start/stop 空操作（docker 由 appcenter 管理）+ status 查容器
│   ├── install_init / install_callback
│   ├── upgrade_init / upgrade_callback
│   ├── uninstall_init / uninstall_callback
│   └── config_init / config_callback
├── wizard/                  安装期表单目录（当前留空，配置走 Web GUI）
├── app/
│   ├── ui/
│   │   ├── config           JSON：fnOS 桌面入口（type=url, port=8000, url=/）
│   │   └── images/          桌面图标（icon_64.png / icon_256.png）
│   └── docker/
│       ├── Dockerfile       python:3.12-slim + uvicorn
│       ├── docker-compose.yaml   container_name=bgi-trigger，host 网络，挂载数据卷到 /data
│       └── app/             FastAPI 应用源码（main.py / settings.py / discovery.py 等）
├── build.sh / build.ps1     打包脚本
└── README.md
```

## 3. 打包

### 一键脚本
```bash
cd nas-app
./build.sh                     # Linux/macOS，使用 PATH 中的 fnpack
# 或
FNPACK=/path/to/fnpack ./build.sh   # 指定 fnpack 路径
```
Windows：
```powershell
cd nas-app
./build.ps1
$env:FNPACK="C:\path\fnpack.exe"; ./build.ps1   # 指定 fnpack 路径
```

### 手动
```bash
cd nas-app
fnpack build
# 产出：bgi-trigger.fpk
```

**预期输出：**
```
Verifying files...
Packing in progress...
Packing successfully. The output file bgi-trigger.fpk can be found in the working directory.
```

`bgi-trigger.fpk` 是一个 gzip 压缩的 tar 包，内含 `app.tgz`、`cmd/`、`config/`、`ICON*.PNG`、`manifest`、`wizard/`。

> `fnpack build` 会校验：manifest 存在且字段合法、config/privilege 与 config/resource 是合法 JSON、ICON.PNG / ICON_256.PNG 存在、app/ 与 cmd/ 存在。任一不满足都会报错。

## 4. 安装到飞牛 NAS

### 方式 A：SSH 命令行
把 `.fpk` 上传到 NAS 后：
```bash
appcenter-cli install-fpk bgi-trigger.fpk
```

### 方式 B：应用中心后台上传
飞牛应用中心 → 上传应用 → 选择 `.fpk` → 安装。

安装后：
- 应用中心出现「BetterGI Trigger」
- 点「启动」，fnOS appcenter 依据 `config/resource` 的 `docker-project` 拉起 `app/docker/docker-compose.yaml`
- fnOS 桌面出现应用入口（由 `app/ui/config` 声明，跳转 `http://<NAS>:8000/`）

## 5. 关键设计点

### 5.1 容器生命周期
Docker 类应用的启动/停止由 **fnOS appcenter** 统一管理（依据 `config/resource` 的 `docker-project`），`cmd/main` 的 `start`/`stop` 为空操作，仅 `status` 通过 `docker inspect <container_name>` 检查容器运行状态。容器名 `bgi-trigger` 须与 `cmd/main` 中读取的 `container_name` 一致。

### 5.2 数据持久化
- `config/resource` 声明 `data-share`：`bgi-trigger` 与 `bgi-trigger/data`
- `docker-compose.yaml` 把 `/var/apps/bgi-trigger/shares/bgi-trigger/data` 挂载到容器 `/data`
- 容器内 `BGI_DATA_DIR=/data`，应用把 `config.json`、`jobs.json` 写在 `/data`
- 卸载/升级时数据保留（除非用户清除共享）

### 5.3 host 网络（自动扫描所需）
`network_mode: host` 让容器共享 NAS 宿主网络栈，从而能枚举 LAN 子网扫描 BetterGI 监听器。`discovery.list_local_subnets` 用 psutil 读取宿主网卡。

> ⚠️ **若 fnOS 不允许应用使用 host 网络**：改 `docker-compose.yaml` 为 bridge 模式，并在应用设置里增加子网配置项（`scan.subnet`），让用户手动填 LAN 子网。代价是失去自动发现，需手填。`config.json` 的 `scan.subnet` 字段已预留。

### 5.4 桌面入口
`app/ui/config` 声明 fnOS 桌面入口：`type=url`，`port=8000`，`url=/`，`allUsers=false`。manifest 的 `desktop_applaunchname=bgi-trigger.Application` 与 `app/ui/config` 中的 `.url` 键一致。

## 6. 升级 / 重新打包

改了应用代码后，重新 `fnpack build` 生成新 `.fpk`，在 NAS 上覆盖安装即可（`appcenter-cli install-fpk` 或后台上传）。`upgrade_init`/`upgrade_callback` 钩子当前为空，如需升级时做数据迁移可在此补充。

## 7. 排查

| 现象 | 原因 / 处理 |
|---|---|
| `Packing failed. File "X" is not valid due to JSON format` | wizard/ 或 config/ 下的 JSON 不合 fnOS schema。wizard 文件可选——留空目录即可，别放占位 JSON |
| `ICON.PNG not found` | 确认 `nas-app/ICON.PNG` 与 `ICON_256.PNG` 存在 |
| 安装后应用启动失败 | SSH 进 NAS 看 `docker logs bgi-trigger`；常见：host 网络被禁、8000 端口被占 |
| 桌面点开白屏 | 确认容器在跑（`docker ps`）、`curl http://<NAS>:8000/health` 通；`app/ui/config` 的 port/url 是否对 |
| 扫不到 Windows 监听器 | host 网络未生效（见 5.3 回退方案）；或 Windows 防火墙挡了 8765 |

## 8. 验证打包是否成功（开发机即可）

```bash
cd nas-app
fnpack build && ls -la bgi-trigger.fpk    # 产出文件即成功
tar tzf bgi-trigger.fpk | head            # 应看到 app.tgz / cmd / config / manifest 等
```
