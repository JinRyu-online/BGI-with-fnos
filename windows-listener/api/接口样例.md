# Windows 监听器接口样例

7 个接口（6 HTTP + 1 WebSocket）的请求/响应样例，供 Apifox 导入或手工 curl 测试。
Apifox 导入：用 `openapi.yaml`（同目录）→ Apifox「导入」→ OpenAPI/Swagger。

## 公共

- **Base URL**：`http://<Windows_IP>:8765`（本机 `http://127.0.0.1:8765`）
- **鉴权**：除 `/health` 外，请求头带 `Authorization: Bearer <api_key>`
- **api_key**：监听器首启自动生成（弹窗显示），或读 `config.toml` 的 `api_key` 字段

设环境变量便于复用（bash）：
```bash
BASE=http://127.0.0.1:8765
KEY=$(python -c "import tomllib;print(tomllib.loads(open('config.toml',encoding='utf-8').read())['auth']['api_key'])")
```

---

## 1. GET /health — 服务身份签名（免鉴权）

NAS 扫描局域网时调此接口识别 BetterGI 监听器（校验 `service == "bgi-trigger"`）。

```bash
curl -s $BASE/health
```

**200 响应：**
```json
{
  "service": "bgi-trigger",
  "hostname": "DESKTOP-WIN",
  "version": "1.0.0"
}
```

---

## 3. GET /tasks — 拉取任务清单

返回 `tasks/tasks.json` 中全部可触发任务。

```bash
curl -s -H "Authorization: Bearer $KEY" $BASE/tasks
```

**200 响应：**
```json
[
  {
    "id": "daily",
    "display_name": "日常一条龙",
    "groups": ["日常一条龙", "关闭游戏"],
    "timeout_min": 90,
    "after_done": "sleep"
  },
  {
    "id": "abyss",
    "display_name": "深渊刷本",
    "groups": ["深渊", "关闭游戏"],
    "timeout_min": 60,
    "after_done": "sleep"
  }
]
```

**401（密钥错误）：** `{"detail":"unauthorized"}`

---

## 4. POST /trigger — 触发任务

启动指定任务，立即返回 `job_id`（异步执行）。

```bash
curl -s -X POST -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"task_id":"daily"}' $BASE/trigger
```

**202 响应：**
```json
{ "job_id": "e4f272964e63" }
```

**404（未知任务）：** `{"detail":"task not found: nope"}`
**409（已有任务在跑）：** `{"detail":"a job is already running"}`

---

## 5. GET /status — 查询任务状态

按 `job_id` 查状态（当前或历史）。NAS 触发后每 10 秒轮询。

```bash
JID=e4f272964e63   # 替换为 /trigger 返回的 job_id
curl -s -H "Authorization: Bearer $KEY" "$BASE/status?job_id=$JID"
```

**200 响应（运行中）：**
```json
{
  "id": "e4f272964e63",
  "task_id": "daily",
  "groups": ["日常一条龙", "关闭游戏"],
  "state": "running",
  "completion_reason": ""
}
```

**200 响应（完成）：**
```json
{
  "id": "e4f272964e63",
  "task_id": "daily",
  "groups": ["日常一条龙", "关闭游戏"],
  "state": "done",
  "completion_reason": "game_exited"
}
```

`state` 取值：`running` / `completing`（30s 反悔窗口）/ `done` / `timeout` / `failed` / `aborted`
`completion_reason`：`game_exited` / `log_keyword` / `timeout` / `error`

**404（任务不存在）：** `{"detail":"job not found"}`

---

## 6. POST /abort — 中止当前任务

常用于任务进入 `completing` 反悔窗口时阻止收尾（如阻止休眠）。

```bash
curl -s -X POST -H "Authorization: Bearer $KEY" $BASE/abort
```

**200 响应：** `{"aborted":true}`

**409（无活动任务）：** `{"detail":"no active job"}`

## 端到端测试样例（顺序执行）

```bash
# 1. 健康检查
curl -s $BASE/health

# 2. 拉任务清单
curl -s -H "Authorization: Bearer $KEY" $BASE/tasks

# 3. 触发日常任务
JID=$(curl -s -X POST -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"task_id":"daily"}' $BASE/trigger | python -c "import sys,json;print(json.load(sys.stdin)['job_id'])")
echo "job_id=$JID"

# 4. 轮询状态（每 10 秒，直到终态）
while :; do
  ST=$(curl -s -H "Authorization: Bearer $KEY" "$BASE/status?job_id=$JID")
  echo "$ST"
  echo "$ST" | grep -qE '"state":"(done|timeout|failed|aborted)"' && break
  sleep 10
done
```

## 2. GET /key — 配对密钥获取（免鉴权）

返回 `api_key` + `hostname`，供 NAS 应用自动填充配对表单，无需用户手敲密钥。

```bash
curl -s $BASE/key
```

**200 响应：**
```json
{ "api_key": "8c38afc257d60668177baad82f7bd351", "hostname": "DESKTOP-WIN" }
```

## 7. WS /ws/logs/{job_id} — 实时日志流

WebSocket 流式推送 BetterGI 实时日志，前端可直接订阅。

```bash
# 用 wscat 等工具
wscat -c "ws://<Windows_IP>:8765/ws/logs/$JID"
```

推送消息示例（JSON）：
```json
{"ts": 1720000000.0, "lines": ["[日常一条龙] 启动..."]}
{"state": {"id":"e4f272964e63","task_id":"daily","groups":[...],"state":"running","completion_reason":""}}
```

> 日志收割器（`log_harvester.py`）内部自动从文件末尾开始收割，历史需主动发 `{"action":"history", "n": N}` 拉取。

## Apifox 导入说明

1. Apifox → 项目 → 「导入」→ 选择 `openapi.yaml`（OpenAPI 3.0）
2. 导入后接口 + 鉴权方案 + 请求/响应样例自动生成（HTTP 接口；WebSocket `/ws/logs` 需单独配置）
3. 配置环境变量：`baseUrl` = `http://<Windows_IP>:8765`，`Authorization` = `Bearer <api_key>`
4. 或用 CLI（需登录）：`apifox import --project <projectId> --file openapi.yaml --type openapi`
