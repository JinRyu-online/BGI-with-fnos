# BetterGI 远程触发系统 — 完整测试步骤文档

> 本文档供晚上回家后**依次手工测试**使用。每个里程碑（M1–M4）独立可测，从简单到完整。
> 测试机：Windows 11（开发机即目标机）+ 飞牛 NAS（x86）+ BetterGI + 原神。
> 全程命令均在 **bash（Git Bash / WSL）** 下执行；Windows 原生 cmd/powershell 用法另注。

## 0. 环境准备清单

测试前确认：

- [ ] Windows 11 已装 Python 3.11+（`python --version`），已装 pip
- [ ] Windows 11 已装 BetterGI，并已**在「全自动-调度器」中配置好调度组**（如 `日常一条龙`、`关闭游戏`）
  - ⚠️ 这是关键前提：`tasks/tasks.json` 里的 `groups` 名必须与 BetterGI 里的组名**完全一致**，否则触发后 BetterGI 找不到组
- [ ] Windows 11 已装原神（`YuanShen.exe` 或国际服 `GenshinImpact.exe`）
  - 完成判定 B 靠监视游戏进程，没游戏无法判定完成（会超时）
- [ ] 飞牛 NAS 已就绪、可 SSH、管理员账号可用
- [ ] 下载 fnpack 工具（`https://developer.fnnas.com/docs/cli/fnpack/`，选 Windows x86 版，改名 `fnpack.exe`）
- [ ] Windows 与 NAS 在同一局域网，互相能 ping 通

**一次性安装测试依赖（开发机）：**
```bash
python -m pip install fastapi uvicorn jinja2 psutil httpx pytest
```

## 1. M1 测试：Windows 监听器

### 1.1 跑单元测试（最快验证代码无误）
```bash
cd windows-listener
python -m pytest tests/ -q
```
**预期：** `69 passed`。若有失败，先别往下走，按报错修。

### 1.2 安装为计划任务
以**管理员身份**打开 PowerShell，进入 `windows-listener` 目录：
```powershell
./install.ps1
```
**预期：**
- 创建 `venv\`、装依赖
- 从 `.example` 生成 `config.toml`、`tasks/tasks.json`
- 注册计划任务 `BGI-Trigger-Listener`（登录后自启 + 最高权限）

### 1.3 配置真实 BetterGI 路径与任务
编辑 `windows-listener/config.toml`：
```toml
[bettergi]
exe_path = "D:\\实际路径\\BetterGI.exe"   # 改成你的真实路径，反斜杠要双写
# log_path 与 log_done_keyword 留空（MVP 完成判定只用 B+超时）
game_processes = ["YuanShen.exe", "GenshinImpact.exe"]
```
编辑 `windows-listener/tasks/tasks.json`，把 `groups` 改成你 BetterGI 里**真实存在**的组名：
```json
[
  {
    "id": "daily",
    "display_name": "日常一条龙",
    "groups": ["日常一条龙", "关闭游戏"],
    "timeout_min": 90,
    "after_done": "sleep"
  }
]
```
> ⚠️ 组名必须与 BetterGI「全自动-调度器」里的组名逐字一致。

### 1.4 首次启动 + 获取密钥
删掉首启标记以触发密钥弹窗：
```bash
cd windows-listener
rm -f .first_run_done
python listener.py
```
**预期：** 弹出「BetterGI Trigger — 密钥」窗口，显示一串 32 位 hex 密钥。**复制保存**（NAS 配对要用）。点「关闭并启动服务」，控制台显示 `serving on 0.0.0.0:8765`。

> 若想再看密钥：`python listener.py --show-key`
> 也可直接读 `config.toml` 里的 `api_key` 字段。

### 1.5 接口手工测试（监听器仍在跑）
另开一个终端：
```bash
KEY=$(python -c "import tomllib;print(tomllib.loads(open('windows-listener/config.toml',encoding='utf-8').read())['auth']['api_key'])")
BASE=http://127.0.0.1:8765

# /health 免鉴权
curl -s $BASE/health
# 预期：{"service":"bgi-trigger","hostname":"<你的主机名>","version":"1.0.0"}

# /tasks 无 key → 401
curl -s -o /dev/null -w "%{http_code}\n" $BASE/tasks
# 预期：401

# /tasks 带 key → 任务清单
curl -s -H "Authorization: Bearer $KEY" $BASE/tasks
# 预期：返回 tasks/tasks.json 的内容

# /key 免鉴权 → 配对信息
curl -s $BASE/key
# 预期：{"api_key":"...","hostname":"..."}
```

### 1.6 真实触发 BetterGI（关键！）
> ⚠️ 这一步会**真正启动原神并执行自动化**。请确保游戏已登录、派蒙界面正常、BetterGI 调度组配置正确。

```bash
# 触发任务
curl -s -X POST -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"task_id":"daily"}' $BASE/trigger
# 预期：{"job_id":"<12位>"}  （HTTP 202）

# 记下 job_id，轮询状态（BetterGI 跑日常要几分钟）
JID=<上面返回的 job_id>
curl -s -H "Authorization: Bearer $KEY" "$BASE/status?job_id=$JID"
# 跑动中预期：{"state":"running",...}
# 跑完预期：{"state":"done","completion_reason":"game_exited",...}
```
**预期全程：**
1. BetterGI 启动 → 原神启动 → 执行调度组 → 执行「关闭游戏」组 → 原神进程退出
2. 监听器检测到游戏进程消失 → `state` 变 `completing`（30 秒反悔窗口）
3. 30 秒后 → `state` 变 `done`，执行 `after_done`（默认 `sleep` → 系统休眠）

> 若 `state` 变 `failed` 且 `completion_reason` 为 `error`：看 `config.toml` 的 `exe_path` 是否正确、组名是否一致。
> 若 `state` 一直是 `running` 直到 `timeout`：游戏进程名不对（国际服/国服差异），检查 `game_processes`。
> 不想真休眠？把任务的 `after_done` 改成 `"none"`（热加载，下次触发生效，无需重启）。

### 1.7 中止测试（可选）
任务进入 `completing` 反悔窗口时（游戏刚退出、收尾前 30 秒），调 `/abort`：
```bash
curl -s -X POST -H "Authorization: Bearer $KEY" $BASE/abort
# 预期：{"aborted":true}，跳过关机/休眠
```

### 1.8 开机自启验证

两种自启方式二选一（详见 `windows-listener/README.md`「开机自启」）：

- **`install.ps1`**（管理员运行）→ 注册 `BGI-Trigger-Listener`（pythonw，无窗口，`/RL HIGHEST`）。重启后 `curl http://127.0.0.1:8765/health` 应能通，且**不弹密钥窗**。
- **`enable_autostart.ps1`** → 注册 `BGI-Trigger-Listener-Console`（可见控制台窗口，默认 `/RL LIMITED`）。重启后会弹出 PowerShell 控制台，显示 `==> 启动 BGI listener ...` 日志；默认端口被占用会跳过启动。排查建议先用此方式。

> v0.2.0 新增：`enable_autostart.ps1` 的可见控制台自启 + SSH/Session 隔离修复（BetterGI 在远程桌面/SSH 下也能正常看到游戏窗口并启动原神）。

## 7. 常见问题排查

### 7.1 NAS 扫不到 Windows 监听器
- **Windows 防火墙**：放行 8765 端口入站。管理员 PowerShell：
  ```powershell
  New-NetFirewallRule -DisplayName "BGI-Trigger" -Direction Inbound -LocalPort 8765 -Protocol TCP -Action Allow
  ```
- 确认监听器在跑：`curl http://<WindowsIP>:8765/health`
- 确认 NAS 与 Windows 同网段（扫描只扫 NAS 所在子网）

### 7.2 配对提示「密钥错误」
- NAS 端粘的密钥与 `windows-listener/config.toml` 的 `api_key` 不一致
- 重看密钥：`python listener.py --show-key`

### 7.3 触发后状态一直 `running` 直到 `timeout`
- 游戏进程名不对：国服 `YuanShen.exe`、国际服 `GenshinImpact.exe`，确认 `config.toml` 的 `game_processes` 含你实际的游戏进程
- BetterGI 没真正启动游戏：检查 `exe_path`、BetterGI 调度组配置

### 7.4 触发后立即 `failed`（completion_reason=error）
- `exe_path` 路径错或 BetterGI.exe 不在该位置
- 组名与 BetterGI 里不一致 → BetterGI 启动但找不到组

### 7.5 监听器没自启
- 计划任务是否注册：`schtasks /Query /TN BGI-Trigger-Listener`
- 是否以最高权限注册（`/RL HIGHEST`）：重跑 `install.ps1`（管理员）
- AUTOLOGON 是否登录了正确账号

### 7.6 `after_done=sleep` 但没休眠
- Windows 未启用休眠：管理员 cmd 运行 `powercfg /hibernate on`
- 想改成不动作：`after_done="none"`

### 7.7 完成判定 C（日志关键字）想启用
- 先实测 BetterGI 日志位置与跑完的关键字
- 在 `config.toml` 填 `log_path` 与 `log_done_keyword`，重启监听器
- 启用后 B/C 任一触发即完成（更准）

### 7.8 fnpack 打包/安装失败
- 确认 `fnpack build` 前目录结构完整（manifest/config/cmd/app/ICON 都在）
- 字段格式以 `fnpack create` 生成的官方骨架为准，别照搬本仓库的 JSON 猜测格式
- 见 `nas-app/README.md` 的覆盖工作流
