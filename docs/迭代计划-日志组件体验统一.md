# 迭代计划：日志组件体验统一（tail -f 跟随 + 浮动回底 + 应用主题化）

> 2026-09-06 v2 · 经 subagent 架构评审修订（8 条必须项全部吸收，含前置发现）。
> 分支：feat/scheduled-tasks（追加 commit）。

## 0. 现状与关键发现（评审前置发现：现有跟随/回底是 no-op）

| 需求 | 现状 | 差距 |
|---|---|---|
| 1. 样式与应用一致 | 深色日志区套在米色应用里，外壳自成体系；详情页 log-frame 与状态页 log-panel 两层包裹样式重复且微妙不一致 | "外部组件嵌入感" |
| 2. tail -f 自动跟随 | **LogPanel 现有实现从未生效过（no-op）**：滚动真实发生在 LogBody 根元素（overflow-y:auto），而 LogPanel 的 ref/scroll 监听挂在外层 `.log-scroll` 包裹（无 overflow、高度恰 240px、不可滚）→ scrollTop 恒 0、scroll 事件永不触发、回底按钮永不出现。这正是用户反馈 2/3 的根因 | **功能性缺陷，本次核心修复目标** |
| 3. 浮动"↓"回底 | 同上 no-op；且形态是文字 pill，需改圆形浮动钮 | 需求 3 |

**结论**：三项指向同一重构——**滚动状态机（在底判定/跟随/回底钮）下沉进 LogBody，与真实滚动元素同层**；LogCard 统一外壳主题；LogPanel 瘦身为实时语义包装。状态页跟随/回底从"完全不工作"变为工作，是本次核心验收基线。

## 1. 设计方案（参考 VS Code 终端 / Lens(kubectl logs -f) / Telegram·ChatGPT 回底钮 / Termius·Vercel 应用内终端卡片）

### 1.1 LogBody 重构为"三明治"结构（回底钮定位契约，评审必须项 4）

```
<div class="log-body-root">            <!-- 新根：position:relative，非滚动 -->
  <div class="log-scroll" ref="scrollEl" @scroll.passive>  <!-- 真实滚动区 -->
    <span v-for 行/> + 加载更多
  </div>
  <transition><button class="log-jump">↓</button></transition>  <!-- absolute 右下，随 root 定位，不随内容滚走 -->
</div>
```
- 滚动状态机内聚 LogBody；LogCard 只提供卡片上下文（无需跨组件事件）。
- props 精简（评审：防蔓延）：`lines` / `followKey?: number` / `height?: string` / `onLoadMore?` / `loadingMore?` / `showBadge?: boolean`（静态详情页显式关闭角标）；**删 `filtered`（死 prop）、`newCount`（内部计）、`showJump`（YAGNI）**。

### 1.2 tail -f 跟随（需求 2；评审必须项 1/2/8）

- 底部判定：`scrollHeight - scrollTop - clientHeight <= 40`。
- **followKey 语义（必须项 1/2）**：
  - 实时页：**`totalLines`**（逻辑计数不封顶——`lines.length` 被 400 行缓冲裁剪封顶，第 400 行后 watch 永不触发、跟随静默失效）；
  - 详情页：**显式版本号**——仅 fetch/loadMore 成功后 +1；**过滤变化不 bump**（消除"过滤触发跟随"的机制耦合）。
- watch 回调只置脏标志，**单 rAF 消费**（双帧：布局完成后再滚；高频日志下强制 reflow 钳到每帧一次）。
- 用户上滑离底 → 暂停跟随 + 记 `newCount += followKey 增量`（角标）；回底后清零。实时页/详情页都生效。
- 详情页"加载更早"视口保持（评审必须项 3，"保持 scrollTop"数值上不成立）：更新前记 `prevScrollHeight`，DOM 更新后 `scrollTop += newScrollHeight - prevScrollHeight`（scrollHeight 差值补偿）；**不依赖原生 overflow-anchor**（Safari/iOS 不支持，Chrome 会掩盖 bug，验收必须 iOS 实测）。原本在底部时 scrollTo bottom 语义正确。

### 1.3 浮动"↓"回底钮（需求 3）

- 40px 圆钮，`rgba(255,255,255,.14)` + backdrop-blur，↓ 字形；**::after inset:-4px 热区外扩至 48px ≥44px**（必须项 7）+ `aria-label="回到底部"`。
- 离底时出现（150ms 过渡，v-show+transition 防闪烁），底部隐藏；点击 `scrollTo({top, behavior})`。
- **平滑滚动降级（必须项 5）**：`'scrollBehavior' in document.documentElement.style` 特性检测，失败降级直接赋值；`prefers-reduced-motion` 用 `matchMedia` 判定后传 `behavior:'auto'`（无障碍，必须项 5b）。
- 角标：仅 `showBadge=true`（实时页）显示离开底部期间的新增行数；详情页显式关闭（避免 loadMore 时"+1000"泄漏，评审 1d）。

### 1.4 主题统一（需求 1；评审必须项 6：头部定案）

**定案：头部条维持深色系**（与日志底同族，避免浅色头部与深色日志的生硬拼接；WS 状态点/mono 字配色沿用现深色变体）：
- `LogCard.vue`（新）外壳：圆角 `--radius-lg`、边框 `--border`、阴影 `--shadow-card`、内边距 token 化；
- 头部条：`--log-head-bg` 为底 + `rgba(201,168,106,.08)` 应用金高光渐变（同族感）；
- **文字对比度达标（4.5:1）**：头部正文/元信息色从 `--log-text-dim`(#8a8474，3.4:1 不足) 调亮为 `#b8b2a2`（≈5.4:1 on #2b3341）；角标底色同步微调；
- props：`title?: string`、默认插槽放元信息（WS 状态点/行数/角标，实时页专属）、`bodyHeight?: string`；对 LogBody 的 props 显式透传对象。

### 1.5 LogPanel 瘦身

- 改为 LogCard 的实时语义包装：头部传入 WS 状态点 + `#job` + 总行数（totalLines）；移除自身滚动跟随/回底实现（下沉 LogBody）；`scrollPaused` 状态从 useLogStream 清理（评审遗漏 5：死状态）。
- `--logpanel-height` 高度单源化：LogBody root 持有（height prop 默认值），LogPanel/详情页只传不定义。

## 3. 测试与验收

前端 vue-tsc + smoke + build:deploy（后端零改动，pytest 回归一次确认）。**手动验收清单**（评审 §4 全量）：
1. **>400 行持续跟随**（缓冲封顶回归——totalLines 语义验证）
2. 状态页：日志流入视口在底部持续跟随；上滑 → 浮钮出现（含新增行数角标）+ 暂停；点钮平滑回底、角标清零、恢复跟随
3. 详情页：进入自动滚到底；"加载更早"在底部点击贴住最新行、在**非底部**点击视口锚定不漂移（iOS 实测——Chrome 原生 anchoring 会掩盖）
4. 过滤激活：不触发跟随、无角标泄漏、回底钮跳过滤结果底
5. 空日志（0 行）：头部正常、浮钮隐藏
6. reduced-motion：无平滑动画
7. smooth 特性检测降级：点钮仍回底（允许无动画）
8. 回底钮热区 ≥44px、aria-label；头部文字对比度 ≥4.5:1
9. WS 终态/错误后头部状态点正确（LogPanel→LogCard props 链回归）

## 4. 风险

| 风险 | 缓解 |
|---|---|
| iOS 惯性滚动吞 rAF 滚动 | rAF 双帧 + passive；真机验证项（清单 3） |
| followKey 高频 watch 风暴 | 置脏 + 单 rAF 消费，reflow 每帧一次 |
| loadMore 覆盖 lines 视口跳顶 | scrollHeight 差值补偿（不依赖 overflow-anchor）；iOS 实测 |
| 圆钮与"加载更多"重叠 | 浮钮 absolute 于 root 右下（视口侧），加载更多在内容流末尾 |
| 深色头部对比度 | #b8b2a2 ≥4.5:1（评审计算）+ 清单 8 验收 |
