# 今晚测试注意事项 — 逐项确认清单

> 配合 `docs/测试步骤.md` 使用。本文档只列**容易踩坑、需特别确认、或未在真机验证**的点，
> 每条给出「如何确认」和「失败怎么办」。建议按顺序逐条打勾。

---

## 一、环境前置（动手前先确认）

### ✅ 1. BetterGI 调度组已配置且组名记录
- **如何确认**：打开 BetterGI → 全自动 → 调度器，确认存在如 `日常一条龙`、`关闭游戏` 等组。
- **为什么重要**：`tasks.json` 的 `groups` 必须与这里**逐字一致**，否则触发后 BetterGI 找不到组、立即 `failed`。
- **失败怎么办**：先在 BetterGI 里建好组，再把组名抄进 `windows-listener/tasks.json`。

### ✅ 2. 原神已登录、停在可操作界面
- **如何确认**：手动启动一次原神，确认能进到派蒙/主界面。
- **为什么重要**：BetterGI 自动化需要游戏在可操作状态；首次启动可能要选服务器、过动画。
- **失败怎么办**：先手动把游戏跑到稳定界面再测触发。

### ✅ 3. 游戏进程名确认（国服/国际服）
- **如何确认**：任务管理器看原神进程名。国服=`YuanShen.exe`，国际服=`GenshinImpact.exe`。
- **为什么重要**：完成判定 B 靠监视这个进程。名字不对 → 任务一直 `running` 直到 `timeout`。
- **失败怎么办**：改 `config.toml` 的 `game_processes`，重启监听器。

### ✅ 4. Windows 防火墙放行 8765 端口
- **如何确认**：管理员 PowerShell 跑
  ```powershell
  New-NetFirewallRule -DisplayName "BGI-Trigger" -Direction Inbound -LocalPort 8765 -Protocol TCP -Action Allow
  ```
- **为什么重要**：不放行 → NAS 扫不到 Windows 监听器（M3 扫描全空）。
- **失败怎么办**：确认规则建上 `Get-NetFirewallRule -DisplayName "BGI-Trigger"`。

## 二、M1 Windows 监听器

### ✅ 5. install.bat 必须管理员身份运行
- **如何确认**：右键 → 以管理员身份运行 cmd → `cd windows-listener` → `install.bat`。
- **为什么重要**：注册 `/RL HIGHEST` 计划任务需要管理员；BetterGI 也需提权。
- **失败怎么办**：提示「请以管理员身份运行」→ 重新用管理员开 cmd。

### ✅ 6. config.toml 的 exe_path 反斜杠双写
- **如何确认**：`exe_path = "D:\\Games\\BetterGI\\BetterGI.exe"`（路径用双反斜杠）。
- **为什么重要**：TOML 里单反斜杠会转义出错 → 路径无效 → 触发立即 `failed (error)`。
- **失败怎么办**：改成双反斜杠，或用正斜杠 `D:/Games/BetterGI/BetterGI.exe` 也可。

### ✅ 7. 首启密钥弹窗会阻塞，需手动关闭
- **如何确认**：`rm -f .first_run_done && python listener.py` → 弹出密钥窗。
- **为什么重要**：弹窗在主线程，**不关窗就不会启动 HTTP 服务**。首次安装时你人在场没问题；但要知道这点。
- **失败怎么办**：复制密钥后点「关闭并启动服务」。想再看：`python listener.py --show-key`。也可直接读 `config.toml` 的 `api_key`。

### ✅ 8. 触发后状态变化的节奏（别误判卡死）
- **如何确认**：触发后 `/status` 会经历 `running`（几分钟，跑脚本）→ `completing`（30 秒反悔窗口）→ `done`。
- **为什么重要**：`completing` 阶段 30 秒不做动作，是设计内的反悔窗口，不是卡死。
- **失败怎么办**：耐心等到 `done`。想中途停：`POST /abort`。

### ✅ 9. after_done=sleep 真的会休眠
- **如何确认**：任务 `done` 后 30 秒，Windows 休眠。
- **为什么重要**：⚠️ 会真的休眠！若没启用休眠功能则无效。
- **失败怎么办**：
  - 启用休眠：管理员 cmd `powercfg /hibernate on`
  - 不想真休眠：把 `tasks.json` 里该任务 `after_done` 改 `"none"`，重启监听器再测。

### ✅ 10. 计划任务自启验证
- **如何确认**：注销重新登录（或重启）→ `curl http://127.0.0.1:8765/health` 能通。
- **为什么重要**：完整链路靠登录后自启。`/SC ONLOGON` 绑定登录事件，AUTOLOGON 登录的必须是配计划任务的账号。
- **失败怎么办**：`schtasks /Query /TN BGI-Trigger-Listener` 看任务在不在；不在就重跑 install.bat（管理员）。

## 三、M3/M4 端到端

### ✅ 11. 扫描耗时 10–30 秒属正常
- **如何确认**：点「扫描局域网」后页面显示「扫描中…」，等 10–30 秒出结果。
- **为什么重要**：要扫整个 /24 子网，别以为卡死反复点。
- **失败怎么办**：超过 40 秒无结果 → 多半是防火墙（见第 4 条）或不在同网段。

### ✅ 12. 多网卡会列出多个 IP，挑 LAN 那个
- **如何确认**：扫描结果可能列出同一主机的多个 IP（如 10.x、172.x 虚拟网卡）。
- **为什么重要**：选错 IP（如 WSL 虚拟网卡）配对后触发可能不通。
- **失败怎么办**：选你 Windows 局域网实际 IP 段的那个（通常 192.168.x 或 10.x）。

### ✅ 13. 配对密钥两边必须一致
- **如何确认**：NAS 配对框粘的密钥 = `windows-listener/config.toml` 的 `api_key`。
- **为什么重要**：不一致 → 配对时 `/api/pair` 返回 401「密钥错误」。
- **失败怎么办**：`python listener.py --show-key` 重看，或读 config.toml。

### ✅ 14. 端到端真触发会启动原神
- **如何确认**：点任务按钮后，BetterGI 启动 → 原神启动 → 跑脚本。
- **为什么重要**：⚠️ 这是真实自动化，会动你的游戏账号。建议先用小任务或 `after_done=none` 测。
- **失败怎么办**：
  - 立即 `failed (error)` → exe_path 或组名错（见 6、1）
  - 一直 `running` 到 `timeout` → 游戏进程名错（见 3）
  - BetterGI 启动但没动作 → BetterGI 自身配置/分辨率问题，查 BetterGI 日志

## 四、FPK 打包部署（最大未验证区）

### ✅ 15. ⚠️ fnOS 是否允许应用用 host 网络（最关键未验证点）
- **如何确认**：装上 `.fpk` 启动后，`docker inspect bgi-trigger` 看 `HostConfig.NetworkMode` 是否 `host`；或在 NAS 上点扫描能否发现 Windows 监听器。
- **为什么重要**：host 网络是局域网自动扫描的前提。若 fnOS 禁止，扫描全空。
- **失败怎么办**（回退方案，见 `nas-app/打包说明.md §5.3`）：
  1. 改 `app/docker/docker-compose.yaml`：删 `network_mode: host`，加 `ports: ["8000:8000"]`
  2. 重新 `fnpack build` 装机
  3. 在应用 Web GUI 里手动填 `scan.subnet`（如 `192.168.1.0/24`）—— `config.json` 已预留此字段
  4. 代价：失去自动发现，需手填子网

### ✅ 16. 容器能否正常启动
- **如何确认**：SSH 进 NAS，`docker ps | grep bgi-trigger` 看在跑；`docker logs bgi-trigger` 无报错。
- **为什么重要**：镜像构建失败、依赖装不上、8000 端口被占都会导致起不来。
- **失败怎么办**：看日志定位。端口冲突改 `app/ui/config` 的 port + docker-compose 端口。

### ✅ 17. 数据持久化生效
- **如何确认**：NAS 上配对一次后，`docker exec bgi-trigger cat /data/config.json` 应有内容；重启容器后配置还在。
- **为什么重要**：若 data-share 挂载没生效，重启丢配置。
- **失败怎么办**：检查 `config/resource` 的 data-share 声明与 docker-compose 挂载路径是否一致。

### ✅ 18. fnpack 打包本身（开发机已实测通过）
- **如何确认**：`cd nas-app && ./build.sh` 输出 `Packing successfully ... bgi-trigger.fpk`。
- **状态**：✅ 已在本机实测通过，这步基本无忧。

## 五、完整链路（最终验收）

### ✅ 19. WOL → AUTOLOGON → 自启 衔接
- **如何确认**：Windows 休眠后，用飞牛 WOL 应用唤醒 → 自动登录 → `curl <WinIP>:8765/health` 通。
- **为什么重要**：三段衔接任一断掉，NAS 触发时监听器没起 → 502。
- **失败怎么办**：分别验证 WOL（飞牛应用）、AUTOLOGON（注册表配置）、计划任务（第 10 条）。

### ✅ 20. NAS 触发时 Windows 已就绪
- **如何确认**：WOL 后别立即触发，等 1–2 分钟（开机+登录+监听器自启）再点任务。
- **为什么重要**：监听器还没起就触发 → `/api/trigger` 返回 502。
- **失败怎么办**：先确认 `/health` 通了再触发。后期可加 WOL+等待编排（P1 阶段）。

## 六、编码/杂项

### ✅ 21. tasks.json 中文组名用 UTF-8 保存
- **如何确认**：用 VSCode/记事本另存为时选 UTF-8。
- **为什么重要**：GBK 保存会导致组名字节不一致，BetterGI 匹配不上。
- **失败怎么办**：重新存为 UTF-8。

### ✅ 22. 别同时开两个监听器
- **如何确认**：只跑一个 `python listener.py`（或只靠计划任务自启）。
- **为什么重要**：两个实例抢 8765 端口，第二个起不来；或行为错乱。
- **失败怎么办**：`netstat -ano | findstr 8765` 看占用，杀多余进程。
