# BetterGI 远程触发系统 — 完整开发方案

> 基于 `docs/背景.md`，经 grill-me 多轮澄清后形成。MVP 优先，预留后期扩展。

## 1. 项目目标

通过飞牛 NAS 上的 FPK 应用，向局域网内一台 Windows 11 电脑发送 HTTP 请求，触发其执行 BetterGI 调度器组（启动游戏 → 跑脚本 → 关闭游戏），并回报执行结果。Windows 端通过已有 WOL + AUTOLOGON 链路开机自启监听器。

**MVP 范围**：跑通「NAS 手动触发 → Windows 执行 BetterGI → 结果回报」核心链路。
**后期**：定时全自动（WOL 编排 + cron 调度）。

## 2. 整体架构

```
┌─────────────────────────┐        HTTP (LAN)         ┌────────────────────────────┐
│  飞牛 NAS (x86)          │  ─────────────────────▶   │  Windows 11 (AUTOLOGON)    │
│  FPK Docker 应用         │   POST /trigger           │  Python 监听器 (计划任务)   │
│  FastAPI + Jinja Web GUI │   GET  /status            │     │                      │
│  - 设备扫描/配对          │   GET  /health            │     ▼ subprocess            │
│  - 任务按钮 (拉自 /tasks) │   GET  /tasks             │  BetterGI.exe --startGroups │
│  - 运行历史/日志          │   POST /abort             │     │                      │
│  - 端口诊断              │                           │     ▼                      │
│  - (后期)WOL+定时        │   ◀─────────────────────  │  原神进程 / BetterGI 日志    │
└─────────────────────────┘   轮询 /status 10s         └────────────────────────────┘
        host 网络模式                                         登录后自启 + 提权
```

## 3. 技术栈

| 端 | 技术 |
|---|---|
| Windows 监听器 | Python 3.12（系统已有）+ venv；FastAPI/uvicorn（或 Flask）；subprocess 拉起 BetterGI；psutil 监控进程 |
| NAS FPK 应用 | Docker 模板（`fnpack create bgi-trigger --template docker`）；容器 `python:3.12-slim`；FastAPI + Jinja2 + Pico.css；JSON 配置；netifaces（子网发现）；python-nmap 或纯 socket（扫描）；APScheduler（后期定时） |
| 打包/部署 | Windows: venv + `schtasks` 注册计划任务；NAS: `fnpack build` → `.fpk` → `appcenter-cli install-fpk` |
| 通信 | 纯 HTTP（内网）；密钥 + IP 自动学习白名单 |

## 4. Windows 监听器详细设计

### 4.1 部署与自启

- 项目目录：`D:\bgi_trigger\`（可改），内含 `listener.py`、`config.toml`、`tasks.json`、`venv\`。
- venv：`python -m venv venv && venv\Scripts\pip install -r requirements.txt`。
- 计划任务（登录后自启 + 最高权限 + 失败重启）：
  ```bat
  schtasks /Create /SC ONLOGON /RL HIGHEST /TN "BGI-Trigger-Listener" ^
    /TR "D:\bgi_trigger\venv\Scripts\pythonw.exe D:\bgi_trigger\listener.py" /F
  ```
  > 用 `pythonw.exe` 无控制台窗口（密钥弹窗由监听器自身用 tkinter 弹出）。
- 实例锁：启动时占用固定端口或文件锁，防止重复拉起。

### 4.2 HTTP 接口

所有接口除 `/health` 外均需 `Authorization: Bearer <key>` + 来源 IP 在信任列表。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/health` | **无需鉴权**，返回 `{"service":"bgi-trigger","hostname":"<主机名>","version":"1.0.0"}`，供 NAS 扫描识别身份 |
| GET | `/tasks` | 返回 `tasks.json` 任务清单 |
| POST | `/trigger` | body `{"task_id":"daily"}`；非 idle 返回 409；否则创建 job、拉起 BetterGI、返回 `{"job_id":"..."}` |
| GET | `/status?job_id=` | 返回任务状态 + 最近日志片段 |
| POST | `/abort` | 中止当前任务（进入 30s 反悔窗口时阻止收尾） |

### 4.3 安全模型

- **密钥**：首次启动生成 32 字节随机 hex，写 `config.toml`，tkinter 弹窗显示可复制（一次性配对）。
- **IP 自动学习白名单**：首次收到「带正确密钥」的请求时，把来源 IP 加入 `trusted_ips`（持久化）；监听器 UI 可查看/清除。非白名单 IP 直接 403。
- **预定义脚本名**：`/trigger` 只接受 `tasks.json` 里的 `task_id`，内部映射到 `BetterGI.exe --startGroups ...`，**绝不接受外部命令行参数**。
- **传输**：纯 HTTP（内网可信）；后期公网暴露再上 HTTPS + 反代。

### 4.4 任务执行与完成判定

- 拉起：`subprocess.Popen([bettergi_exe, "--startGroups", *groups])`，`groups` 含任务配置的组名 + `"关闭游戏"`。
- **完成判定**（任一触发即完成，先到先得）：
  - B：轮询 `psutil`，`YuanShen.exe` / `GenshinImpact.exe` 进程消失。
  - C：tail BetterGI 日志，命中可配关键字（**MVP 禁用**，路径/关键字留空）。
  - D 兜底：任务 `timeout_min`（默认 90）超时 → 标记 `timeout`，尝试清理残留进程。
- **收尾**：完成判定命中后进入 30s `completing` 反悔窗口（可 `/abort`），随后按任务 `after_done` 执行：
  - `sleep`（默认）→ `shutdown /h`
  - `shutdown` → `shutdown /s /t 0`
  - `lock` → `rundll32 user32.dll,LockWorkStation`
  - `none` → 不动作
- 完成后可选 kill 残留 `BetterGI.exe`。

### 4.5 状态机

```
idle ──/trigger──▶ running ──B/C命中──▶ completing(30s) ──▶ done
                       │                      │  /abort       │
                       └──timeout──▶ timeout   └────────────▶ aborted
                                       │
                                   (after_done: sleep/shutdown/lock/none)
```

历史：保留最近 20 条 job 的日志（`var/jobs/<job_id>.log`）。

### 4.6 配置文件

**`config.toml`**（Windows 端）：
```toml
[server]
host = "0.0.0.0"
port = 8765

[auth]
api_key = ""                 # 首次启动自动生成并回填
trusted_ips = []             # 自动学习

[bettergi]
exe_path = ""                # BetterGI.exe 路径，留空则尝试注册表/常见路径探测
config_path = ""             # BetterGI 调度器配置路径，留空则不自读（走手填 tasks.json）
log_path = ""                # BetterGI 日志路径，留空则禁用完成判定 C
log_done_keyword = ""        # 完成关键字，留空则禁用 C
game_processes = ["YuanShen.exe", "GenshinImpact.exe"]

[execution]
default_timeout_min = 90
default_after_done = "sleep"
grace_seconds = 30
keep_history = 20
```

**`tasks.json`**（任务清单，唯一真相源）：
```json
[
  {
    "id": "daily",
    "display_name": "日常一条龙",
    "groups": ["日常一条龙", "关闭游戏"],
    "timeout_min": 90,
    "after_done": "sleep"
  }
]
```

### 4.7 BetterGI 调用约定

- 形态：调度器组（`--startGroups`），**不用**一条龙/单 JS 脚本（命令行不支持）。
- 用户需在 BetterGI「全自动-调度器」里预先配好组（如 `日常一条龙`、`关闭游戏`）。
- 组名必须与 `tasks.json` 中 `groups` 完全一致。
- BetterGI 需管理员权限 → 计划任务 `/RL HIGHEST` 满足。

## 5. NAS FPK 应用详细设计

### 5.1 项目结构（fnpack Docker 模板）

```
bgi-trigger/
├── app/
│   ├── ui/                       # 静态资源（图标等）
│   └── docker/
│       ├── docker-compose.yaml   # host 网络 + 挂载 etc/var
│       ├── Dockerfile            # python:3.12-slim + pip install
│       └── app/                  # FastAPI 应用源码
│           ├── main.py
│           ├── templates/        # Jinja2 页面
│           ├── static/
│           └── requirements.txt
├── cmd/                          # 生命周期脚本（main 处理 start/stop/status）
├── config/
│   ├── privilege                 # 权限声明（含 host 网络）
│   └── resource                  # 资源声明（端口等）
├── wizard/                       # 安装/配置表单
├── manifest                      # appname/version/source=thirdparty/platform=x86/ctl_stop=true
├── ICON.PNG
└── ICON_256.PNG
```

### 5.2 Docker / 网络

- `network_mode: host`（扫描局域网必需，需 `config/privilege` 声明）。
- 挂载：`etc`（`TRIM_PKGETC`，存 `config.json`/`schedules.json`）→ 容器内 `/etc/app`；`var`（`TRIM_PKGVAR`，存 `app.log`/历史）→ `/var/app`。
- 端口：容器内 FastAPI 监听 `8000`；host 模式下直接占用宿主 8000，fnOS 统一网关反代或在应用中心直接跳转。

### 5.3 Web GUI 面板

| 面板 | 功能 |
|---|---|
| **设备** | 「扫描设备」按钮 → 主动扫子网 → 对候选 IP:8765 调 `/health` → 列出身份匹配的监听器（主机名+IP）；点击选中 → 粘贴密钥 → 「测试连接」→ 保存为默认目标 |
| **任务** | 从默认目标 `/tasks` 拉取 → 渲染触发按钮（`display_name`）；点击 → `POST /trigger` → 卡片进入运行中 |
| **运行中/历史** | 触发后每 10s 轮询 `/status`；终态后停止轮询、拉日志展示；历史列表点开看每次任务状态+日志 |
| **端口诊断** | 「测试连接」探活监听端口 + `/health`；「端口扫描」对目标 IP 扫可配端口列表（默认 `[22,3389,445,8765,8000-8100]`），列出开/关 |
| **设置** | 编辑默认目标、密钥、扫描端口列表、子网段（可选覆盖自动探测）；后期：定时规则、WOL MAC |
| **(后期)定时** | APScheduler cron 规则增删；WOL 编排开关 |

### 5.4 自动发现机制

- 子网发现：`netifaces.ifaddresses()` 找非 loopback 的 IPv4 接口 → 推导 CIDR（如 `192.168.1.0/24`）。
- 扫描：对子网每个 IP 并发 TCP connect 候选端口（默认 8765），超时 1s；通的再 `GET /health`，校验 `service == "bgi-trigger"` 才入列。
- 结果带主机名，供小白辨识。

### 5.5 配置文件（NAS 端 `etc/config.json`）

## 6. 小白使用流程

1. Windows：解压 listener → 运行安装脚本（建 venv + 注册计划任务）→ 桌面弹窗显示密钥。
2. NAS：安装 `.fpk` → 打开应用 → 「扫描设备」→ 列出局域网 BetterGI 监听器 → 点选 → 粘密钥 → 「测试连接」✅。
3. 点任务按钮 → 等待完成 → 看日志。全程零 IP 查找。

## 7. 实施里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| **M1** Windows 监听器 | FastAPI 五接口 + 状态机 + 完成判定 B/超时 + 配置 + 计划任务部署脚本 + 密钥弹窗 | 可手动 curl 触发跑通 BetterGI |
| **M2** NAS FPK 骨架 | fnpack Docker 模板 + FastAPI+Jinja 框架 + host 网络 + 配置持久化 | 应用可装可跑、能访问 Web GUI |
| **M3** 发现与配对 | 子网扫描 + `/health` 识别 + 密钥配对 + 默认目标保存 | 小白流程跑通 |
| **M4** 触发与回报 | `/trigger` + 10s 轮询 `/status` + 历史/日志展示 | **MVP 完成**：端到端跑通 |
| **M5** 端口诊断 | 测试连接 + 端口扫描面板 | 诊断工具就绪 |
| **P1(后期)** WOL 编排 | magic packet + 唤醒后 health 等待 + 超时处理 | 全自动唤醒 |
| **P2(后期)** 定时调度 | APScheduler cron + WOL 编排串联 | 每天定时全自动 |

## 8. 待验证风险项

| 项 | 风险 | 兜底 |
|---|---|---|
| BetterGI 跑完调度组是否自动退出 | 未知 | 完成判定用 B（游戏进程）而非等 BetterGI 退出；B 已覆盖 |
| fnOS 是否允许应用 host 网络 | 未实测 | 若不行，退 bridge + wizard 填子网（牺牲一点小白体验） |
| BetterGI 日志路径/格式 | 未核实 | C 判定可配+留空，MVP 不依赖 |
| BetterGI 配置文件路径 | 未核实 | 自读预填可配+留空，走手填 `tasks.json` |
| BetterGI 需要的 admin 是否真必需 | 官方 bat 强制 | 计划任务 `/RL HIGHEST` 满足，最稳 |
| `pythonw.exe` + tkinter 弹窗在 AUTOLOGON Session 是否正常 | 一般可用 | 若不行，密钥改为首次写文件 `config.toml` 让用户手开查看 |
