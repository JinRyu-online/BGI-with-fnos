# 迭代计划：历史任务日志回看

> 2026-09-06 v2 · 经 subagent 架构评审修订（7 条必须项全部吸收）。
> 数据链路经只读调查确认（Windows 端已有 job 级落盘、harvester 5 分钟/50 行限制、NAS WS 代理无状态）。
> 分支：feat/scheduled-tasks（追加 commit）。

## 0. 需求与数据现状

需求：历史页任务卡片点开能看**当时**的日志。

数据盘点（调查结论）：
- Windows harvester 已把每 job 全量日志落盘 `windows-listener/log/{job_id}.log`（永久，无人删）；但**当前部署 config.toml `log_path=""` → harvester 未启用**（前置提示项）。
- harvester 内存 deque 50 行、终态 5 分钟清理 → WS 回放只够"刚结束看一眼"；且 listener WS 协议**每次新连接都重放 recent(3)+since(0) 最近缓冲**（无 seq 持久化）。
- NAS WS 代理纯透传不落盘；无日志 HTTP 接口；前端 LogPanel 深度耦合 WS 单例。

## 1. 方案选型：B2 主动录制（主）+ tee 角色接管（辅）

**B2（核心）**：NAS 在触发成功后（手动 `/api/trigger` 与定时 `_execute_schedule` 两条路）由 **NAS 后台 daemon 线程 `asyncio.run(_record_ws(job_id))`** 连 listener WS 录整场日志到 `{BGI_DATA_DIR}/jobs_log/{job_id}.log`。与用户在线与否解耦（定时任务凌晨跑也录全）、数据在 NAS 盘（compose 已持久化 /data）。单槽状态机保证同时最多 1 个录制线程；线程模型与现有 reconcile/scheduler 同构。

**tee（辅）**：WS 代理收帧顺带写盘——但采用**原子角色接管**模型（见 §3.2），不是无脑旁路。

**不做**：Windows 暴露 /logs/{job_id} 读接口（B2 已覆盖本地化需求，留作将来增强）；BetterGI 按天日志切片（多 job 混行不可靠）。

前置提示（汇报时必须告知用户）：当前部署 config.toml `log_path=""` → harvester 未启用 → **无日志可录**，需先配置 `bettergi.dir`/`log_path`；详情页空态文案含此引导。

## 2. UI 设计（参考 GitHub Mobile 详情页 sticky 头、Termius/DSM 日志查看器、微信小程序日志反馈）

**入口**：HistoryCard 整卡可点 + 右侧 › chevron（--text-3 弱化）→ **独立全屏路由** `/logs/:jobId`（不用弹层：内容长、路由化刷新不丢、可返回）。

## 3. 后端设计（NAS 端）

### 3.1 新模块 `job_log_store.py`（仿 HistoryStore 风格）

- **job_id 白名单校验** `valid_job_id(j) -> bool`：`^[A-Za-z0-9_-]+$`（uuid hex+连字符）；非法一律拒绝——`path_for`、`GET /api/logs`、WS 代理拼上游 URL（main.py 现有 :927 处一并加）三处同用。防路径穿越。
- `path_for(job_id)` → `{BGI_DATA_DIR}/jobs_log/{job_id}.log`
- `append_lines(job_id, lines)`：追加写（append-only 行缓冲，读侧容忍残行按最后换行截断）
- `read_tail(job_id, n)`：**反向分块读**（seek 末尾按 64KB 块回退数换行），禁止整文件读入内存
- `has_log(job_id)`；`try_acquire_recorder(job_id) -> bool` / `release_recorder(job_id)`（threading.Lock 原子，B2 与 tee 的唯一写者仲裁）；`set_recorder(job_id, bool)`（请求路径同步标记）
- 保留策略（本轮顺手做最简版）：`prune(keep=100)`——文件数超 keep 删最旧；在每次 `append_lines` 新 job 首行时触发。

### 3.2 录制器与 tee（main.py）

- **flag 置位时机（评审必须项）**：`api_trigger` 与 `_execute_schedule` 在成功拿到 job_id 后、**返回/投递前同步** `set_recorder(job_id, True)` 并 `try_acquire_recorder`——凡 NAS 触发的 job，任何后续 tee 连接建立时 flag 必为 True，无竞态窗口。B2 线程 `finally` 里 `release_recorder`。
- **B2 录制**：daemon 线程内 `asyncio.run(_record_ws(job_id))`：
  1. 初始连接**短退避重试 1s/2s/5s 共 3 次**（定时任务 listener 刚就绪的瞬时失败常见；重试耗尽→写 `[系统] 日志录制失败：无法连接监听器` 停）；
  2. 收帧：`{"ts","lines"}` → `append_lines`；`{"last":true}` → 正常停；`{"error":...}` → 写 `[系统] 日志录制中断：<原因>` 停（listener 重启即此路径——**不假设录制是全量**，详情页不写"完整日志"字样）；
  3. **兜底时长上限**：`MAX_TASK_DURATION_SEC(24h) + 300s`（listener 同款常量；NAS 侧不查 task timeout_min）；
  4. **中途重连**（网络抖动断开且未收 last/error）：退避重试恢复录制，恢复后先写 `[系统] 录制接续，可能重复最近缓冲` 标记行——**不做按内容去重**（WS 协议无持久 seq，重放必然发生；日志合法重复可接受，去重必误伤）；
  5. `finally`：`release_recorder`。
- **tee 角色接管**：`api_ws_logs` 在上游连接成功后 `try_acquire_recorder(job_id)`——成功者（如 NAS 重启后 flag 丢失、job 仍在跑的场景）本连接生命周期内独占写盘（解析 `{"ts","lines"}` 帧 try-parse，失败静默跳过），断开时 `release_recorder`；失败者（B2 在录）纯透传不写盘。**取消旧方案"连接时看一眼 flag"的判定**（202 返回后前端立即 openLogStream，存在 flag 未置位窗口——已由同步置位+接管模型双保险关闭）。

### 3.3 读取接口

`GET /api/logs/{job_id}?tail=N`：
- `valid_job_id` 校验，非法 400；
- `tail` **默认 1000、上限 5000**（钳制），无"全部"模式（移动端渲染与内存保护）；
- 文件不存在 → 404 `{"detail": "无日志记录"}`；
- 响应 `{"job_id", "lines": [...]}`（strings，前端 classifyLog）。

### 3.4 spa_fallback 深链修复（评审发现的既有 latent bug，本轮必须修+测）

`main.py` spa_fallback 现对含 `/` 的 rest 直接 404——两段路由 `/spa/logs/{id}` 刷新必 404。改为：**rest 含 `/` 时，末段无扩展名 → 回退 index.html；末段带已知资产扩展名（.js/.css/.png/.ico/.map/.webp/.json）→ 404**。补 NAS pytest + smoke 两层用例。

## 4. 前端设计

- **LogPanel 拆分（评审必须项，禁止复制样式）**：从 LogPanel.vue 抽出展示子组件 **`LogBody.vue`**（props: `lines: LogLine[]`、`filtered?: boolean`；不含 WS 状态点/总数角标），实时页 LogPanel 与详情页共用；三色高亮/等宽/pre-wrap/加载更多按钮在 LogBody 内。
- 路由 `/logs/:jobId`（注册在 catch-all 之前；router base /spa/ 已有）。
- `useLogHistory.ts`：`fetch(jobId, tail)` → api.getLogs；state `{loading, lines, keyword, visible}`；过滤 computed（大小写不敏感 includes）+ 250ms 防抖；"加载更多"递增 tail 上限分页取。

- types.ts `LogBundle`；useApi `getLogs(jobId, tail?)`；mock/server.ts 补 `getLogs`（返回假行，前端可离线开发）。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| B2 线程泄漏 | 兜底时长 24h+300s 上限；daemon 线程 |
| jobs_log 增长 | prune(keep=100) 本轮做；单文件大小读侧 tail 反向分块保护 |
| 部署 config.toml log_path 空 → 无日志 | 空态引导 + 汇报提示用户配置 |
| WS 代理解析开销 | tee 路径 try-parse 失败静默跳过 |
| tail=1000 看不到早期日志 | "加载更多"分页递增 |
| 重连重放重复行 | 接受 + `[系统]` 标记行明示 |
