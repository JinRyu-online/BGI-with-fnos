# 迭代计划：日志详情页双滚动条治理

> 2026-09-06 v2 · 经 subagent 评审修订（5 条 blocking 全部吸收：改 in-flow height:100% 方案、定高链补全、contain 作用域定案、overflow 兜底、验收补齐）。
> 分支：feat/scheduled-tasks（追加 commit）。

## 0. 根因

详情页 = 可滚动的 `.page`（abspos inset:0 + overflow-y:auto + padding 含 tabbar 避让）内嵌固定 420px 日志滚动区 → **嵌套滚动**：日志区滚到边界后 scroll chaining 带动外层页面滚（用户看到"两个滚动条同时动"）；两个滚动上下文各自显示滚动指示。

## 1. 主方案：in-flow `height:100%`，页面不再滚（评审定案 (a)）

**不采用满铺 inset:0**（评审 1.4：与 tabbar 避让自相矛盾、绕圈复杂度净增）。改为：

```
.detail-page（height:100%; display:flex; flex-direction:column; overflow-y:auto ← 兜底）
  ├─ .detail-header（flex-shrink:0 —— 返回 + 摘要卡；去 sticky 语义，天然固定）
  ├─ .toolbar（flex-shrink:0）
  └─ .log-section（flex:1; min-height:0; display:flex; flex-direction:column —— 唯一滚动域容器）
       └─ LogCard → LogBody（日志滚动区，吃满剩余高度）
```

- `.detail-page` 用 **in-flow `height:100%`**（父级 `.page` 是 abspos 高度确定）= content-box 高，**`.page` 的 padding 原样保留**（含 tabbar/safe-area 避让——不重新实现），改动面最小。
- `.detail-page` `overflow-y:auto` 兜底：日志态内容恰好填满不产生滚动；错误态/空态超长文案（小屏+三段引导）可滚不被裁。
- header 的 `margin: 0 -4px`、`.summary-card` 的 `margin: 0 4px`、`z-index:5` **原样保留**——`.page` padding 未变，负 margin 的"借边"语义继续成立（评审 1.2 采纳"语义不变"分支）；去 sticky 属性即可。

## 2. 定高链（评审 blocking 1：height:100% 直通链断裂修补）

百分比高度对 auto 父级失效——四层链每层都要定高：

| 层 | 规则 |
|---|---|
| `.detail-page` | `height:100%; display:flex; flex-direction:column; overflow-y:auto` |
| `.log-section`（新增包裹） | `flex:1; min-height:0; display:flex; flex-direction:column` |
| `.log-card`（LogCard 根） | `flex:1; min-height:0; margin-bottom:0; display:flex; flex-direction:column`（原 margin-bottom 12px 在定高 flex 里吃高度，改由 detail-page padding 承担） |
| `.log-body-root`（LogBody 根） | `flex:1; min-height:0` |
| `.log-scroll` | 保持内联 `height:100%`（父级已定高，百分比生效） |

**状态页影响论证**：LogCard 在状态页无 flex 上下文（LogPanel 直接放 .page 流里），`flex:1` 不生效、`.log-body-root` 的 `flex:1; min-height:0` 在 block 容器里也不生效 → `.log-scroll` 仍走 `--logpanel-height:240px`，**状态页零变化**；纳入验收回归。

## 3. overscroll-behavior 作用域定案（评审 blocking 3：矛盾裁决）

**contain 不进 LogBody 全局**（状态页 240px 小窗滚到边界带动页面滚动是预期体验，加 contain 是可感知回退）。实现：LogBody 加 prop `scrollChaining?: 'allow' | 'contain'`（默认 allow=现状），**详情页传 'contain'**，通过 `.log-scroll` 动态 style 设置。

## 4. 其他决策（评审遗漏项吸收）

- **桌面端 844px 手机框**：`.detail-page height:100%` 照常工作（`.page` 高度被 shell max-height 约束）；鼠标滚轮链动行为纳入验收（§5.1）。
- **键盘弹出**：过滤输入聚焦（iOS visual viewport 缩小、layout viewport 不变）→ toolbar 固定在顶部仍可见；纳入验收（§5.2）。
- **hit-badge 显隐改变 LogCard 高度** → `.log-scroll` clientHeight 突变可能使 atBottom 判定漂移、回底钮闪现：`onScroll` 逻辑不变，但 **hit-badge 从工具条下方独立行移入 toolbar 行内**（不改变纵向布局高度）——消除突变源。
- **transition**：`.page` pageIn 动画对 in-flow 子元素无碍；回底钮锚定 `.log-body-root` 底部（在 .page padding 之内，不落 tabbar 避让区）——纳入验收（§5.4）。
- **420/280 断点删除**：新布局自适应剩余高度，断点与 `:deep + !important` hack 一并删除（该断点是旧布局脆弱性的止痛药，主方案成立后自然消亡）；全仓 grep 确认无其他引用。

## 5. 测试与验收

前端 vue-tsc + build:deploy + smoke（无路由变化）；后端零改动，pytest 回归一次。

手动验收清单：
1. 详情页滑动日志区：只有日志内容滚，头部/工具条纹丝不动（无双滚动）；
2. 日志滚到边界继续滑：不带动页面（contain 生效）；
3. 桌面 844 手机框 + 窗口 <892px（max-height 生效）+ 鼠标滚轮滚动/链动；
4. 过滤输入聚焦弹键盘：toolbar 仍可见、收起后布局复原；
5. 过滤词使 hit-badge 出现/消失：日志区高度稳定、跟随状态不漂、回底钮不异常闪现；
6. 回底钮位置可达、不被底部避让区遮挡；"加载更早"按钮在日志流末尾可达；
7. 错误态/空态超长文案可滚动不裁切；
8. 横屏（~390px 高）布局；
9. 深链 `/spa/logs/:id` 直达 + 返回 fallback；
10. StatusPage 240px 小窗 + 页面滚动行为回归（不受 contain 影响）；
11. 历史 tab ↔ 详情往返多次无状态串扰；
12. 旧 iOS（无 overscroll-behavior）降级仅靠主方案，行为可接受。
